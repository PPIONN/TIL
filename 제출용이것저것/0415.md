# UHT / UBT (건물 짓기 전, 설계도를 검토하는 감독관들)
C++ 코드를 작성하고 빌드를 누르면, 컴파일러(Visual Studio)가 일하기 전에 언리얼 전용 감독관들이 먼저 등판합니다.

# UHT (Unreal Header Tool)

 헤더 파일(.h)을 슥 훑어보며 UCLASS(), UPROPERTY(), UFUNCTION() 같은 매크로를 찾아냅니다.
"이 변수는 나중에 에디터에 노출할 거네?", "이 함수는 블루프린트에서 쓸 거네?" 하고 메모합니다. 이 메모를 바탕으로 언리얼이 이해할 수 있는 특수한 코드(.generated.h)를 자동으로 생성해 줍니다.

# UBT (Unreal Build Tool)

 빌드 과정을 총괄합니다.
"어떤 파일을 먼저 컴파일해야 하지?", "이 프로젝트는 윈도우용인가 안드로이드용인가?"를 판단해서 컴파일러에게 일을 시킵니다. 복잡한 C++ 빌드 설정을 따로 안해줘도 알아서 해줍니다.

# 리플렉션 (Reflection)

C++은 원래 "내 클래스에 어떤 변수가 있는지" 스스로 알지 못하는 딱딱한 언어입니다. 하지만 언리얼은 이걸 가능하게 만듭니다.
프로그램이 실행 중에 자기 자신의 구조(클래스 이름, 변수 타입 등)를 스스로 조사할 수 있는 능력입니다.

에디터 노출: UPROPERTY를 붙이면 디테일 패널에 변수가 뜨는 이유가 바로 리플렉션 덕분입니다.

가비지 컬렉션: "이 포인터가 아직 사용 중인가?"를 리플렉션으로 추적해서 메모리를 관리합니다.

블루프린트 연동: C++ 함수를 블루프린트에서 호출할 수 있는 것도 리플렉션이 중간 다리 역할을 하기 때문입니다.

# CDO (Class Default Object)

클래스마다 딱 하나씩 생성되는 기본 객체입니다. 엔진이 켜질 때 모든 클래스의 CDO가 생성됩니다.

예시로 여러 액터를 10개 스폰해도, 그들의 기본 로테이션이나 스케일은 CDO(모델 하우스)에 적혀 있는 값을 보고 복사해옵니다.

성능 최적화: 객체를 새로 만들 때마다 일일이 초기화하는 게 아니라, 이미 만들어진 CDO를 '복사'만 하면 되니까 훨씬 빠릅니다.

기본값 복구: 에디터에서 값을 수정하다가 '노란색 화살표(기본값으로 되돌리기)'를 누르면 바로 이 CDO에 저장된 값으로 돌아갑니다.

# 한눈에 정리하는 흐름도

1. 코드에 매크로코드(UPROPERTY 등)를 쓴다.
(UHT) 특정 매크로 코드를 읽고 리플렉션 데이터가 필요하다 느껴 보조 코드를 만든다.

2. VS와 같은 컴파일러에 UBT가 UHT의 보조 코드를 같이 빌드하게 명령한다.

3. 엔진 실행되며 리플렉션 시스템이 구축되고, 각 클래스의 CDO가 메모리에 올라간다.

4. 새로운 캐릭터를 만든 후 게임 플레이시 CDO를 본떠서 복제본이 탄생한다.
