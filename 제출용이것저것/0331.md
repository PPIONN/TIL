# 레포지토리 ?

```text

로컬 레포지토리 : 내 컴퓨터의 로컬 폴더, 리모트 레포지토리를 clone 한 상태의 폴더를 의미한다.
리모트 레포지토리 : 깃허브(Github)클라우드에서 제공해주는 원격 저장소, 현재 제작중인 Til을 제작하는 공간 또한 리모트 레포지토리이다.


로컬 레포지토리 제작 방법 :
1)내 컴퓨터 내에 폴더를 하나 만든다.
2)폴더에 들어가서 주소창에 cmd를 검색한다. 명령창에 git clone 리모트 레포지토리 주소
3)폴더가 하나 만들어질것이다. 해당 폴더가 로컬 레포지토리이다.
```

```text
Pull : 리모트 레포지토리에 올라온 파일을 내 로컬 레포지토리로 가져와서 합친다. Pull의 내부 동작 (Fetch + Merge). Fetch와 Merge는 다음에 설명.
Pull 버튼을 누른 화면이다. 리모트 레포지토리의 브랜치를 결정하게 해주는 창이 있다.
처음엔 main을 누르고 확인을 누르면 문제없다. 협업자가 있다면 각자의 Brnach를 만들어서 둥지짓기를 하는게 충돌 예방에 좋다.
```

```text

Commit : 본인이 무슨 파일을 올릴지 추릴 수 있다. cmd 창에서 올릴시 add가 무슨 파일을 올릴지 추리는 기능을 한다.
Unstaged files 내 로컬레포지토리의 파일을 확인해 수정되어있는 파일을 리모트 레포지토리에 올릴 수 있는 리스트를 보여준다.
소스트리는 그 기능에 가시화를 더 해준셈. 감사할따름이다.
stage selected를 눌러서 하나씩 올려도 되고 staged all을 눌러서 한꺼번에 올려도 된다. 자신이 선택해야한다.
밑에 메시지로 어떤 부분을 수정했는지 내가 원하는 말을 남길 수 있다. 수정한 부분을 자세하게 적자.
```

```c++

Push : commit을 문제없이 했는가? 그렇다면 다음 단계가 있다. 우린 아직 깃허브 리모트 레포지토리에 파일을 올린게 아니다.
그 기능을 하는게 Push 이다. Push 버튼을 누르면 창이 뜬다. Branches to push 박스부터 보자.

Push? : 어떤 로컬 레포지토리 브랜치의 내용을 Push하고 싶은지 묻는것이다.
현재 난 저장저장2를 branch로 사용중이다. 다른분들은 이름을 이쁘게 적자.

Local branch : 어떤 로컬 브랜치를 사용할것인지 묻는것이다.
Remote branch : 어떤 리모트 레포지토리의 branch에 Push 하고싶은지 물어보는것이다.
처음 리모트 레포지토리를 만들면 main이 만들어진다. main에 해주자. 자신이 나만의 둥지를 갖고싶다면 branch를 만들고 해당 branch로 바꾸자.

문제 없다면 Push를 누르자.
```
